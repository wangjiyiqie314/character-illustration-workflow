# 参考资料的作用与边界

先描述画面中的事件、主焦点和情绪，再按作用选择参考。可以分别使用构图、色彩、光影、边缘或叙事资料；不必填满所有槽位。参考固定后，不在每轮任意换图。

本发行版不提供私有参考图片、策展目录或采集 CLI。需要资料时，由项目维护者提供有适当权限的图片，记录来源、用途、哈希与授权范围。下载成功和收藏数据不是再分发许可。

`tools/reference-core.mjs` 保留原有可测试函数：

- `sampleReferences(catalog, options)`：按 seed、roles、mood、format、grammar 做固定排序和约束筛选，返回一至三项。
- `verifyCatalog(catalog, root)`：核验目录字段、来源记录、图片哈希与原有策展规则。
- `auditPlan(plan, root)`：检查目录版本、选图结果、路径和哈希是否仍匹配。

这些规则沿用特定目录结构，包括数值收藏门槛和来源证据格式；它们不是任意图库的即插即用管理界面，也不证明审美质量。可从合成测试理解所需字段，不要把测试数据当成真实作品证据。seed 不控制图像模型。

实际生成时，每张图写清借鉴作用与禁止迁移的内容。艺术参考不应覆盖本项目身份、姿态和服装设计；人物来源与作者归属可以记录，画风要求应使用具体视觉语言。不得移植他人签名、水印或角色设计细节。

`deliver.mjs prepare` 固定本项目阶段参考，不接管外部艺术库。外部输入需另存实际顺序、作用与哈希；计划存在不证明工具接收了图片。

如果参考持续带回已移除的阴影或纹理，可以在得到相应决策授权后撤下生成输入、保留为生成后对照，并记录改变和身份漂移风险。不能事后改写引用历史来掩盖失败。
