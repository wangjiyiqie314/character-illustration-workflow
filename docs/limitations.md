# 已知限制

- 没有生图后端、模型权重、模型种子控制或分层文件输出。生成记录不能保证重现模型输出。
- review 模式需要人工选择证据文本，但不认证文件作者；助手仍须核实真实授权。demo 模式不能被视为人工定稿。
- CLI 输入为可信本地配方／项目文件，不提供多租户隔离。不要导入来源不明的项目记录，也不要把预览服务暴露到公网。
- 本地状态采用文件写入，未实现事务、并发写锁或崩溃恢复；同一个 run 不应由多个进程同时修改。
- 从零路线是 schema 2 默认；`workflow: direct_first` 的配方需要 `direct` 与 `refine` 阶段。通用页面不包含所有历史批次专用交互。
- 生成中的页面会链接尚未创建的报告和验证文件。完成项目后补充 `REPORT.md`；先成图页面还提供 `MANUAL_RETOUCH.md` 链接，可记录尚未执行的人工修绘项。
- `verify` 要求每个规划阶段都有当前选择、图片／提示词哈希一致、图片计数符合配方，并存在页面与报告；部分完成项目返回非零是预期行为。它不执行独立图像审美检查。
- `ingest` 记录源图片的本机绝对路径，事件与人工证据也可能有隐私。`runs/` 默认不纳入版本控制；公开任何自己的项目前须单独导出和审查，不能整目录上传。
- 三份配方是重新编写的流程示例。修改角色时应同步每个 prompt；本工具不会自动把 attributes 注入所有提示词。
- 测试 fixture 是合成 2×2 PNG；通过测试不等于完成真实图像生成测试。
- 许可证尚未指定。维护者的图片展示批准不构成对公众的通用素材授权。
